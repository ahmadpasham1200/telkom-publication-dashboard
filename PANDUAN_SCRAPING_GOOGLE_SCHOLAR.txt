--------------------------------------------------------------------------------
1. RINGKAS
--------------------------------------------------------------------------------

Pipeline: Google Scholar -> RAW (berhenti). Tidak ada cleaning/enrichment/
STAGING/CORE. Jangan pakai --load-core.

Perintah satu profil (dari root project):

    python src/pipeline/run_pipeline.py --id 8kDg_v4AAAAJ

Perintah banyak dosen (dari Excel):

    python src/pipeline/run_batch.py --file "data dosen/Data dosen.xlsx" --lanjut

Keduanya menyimpan hasil ke database yang ditunjuk .env, yaitu
publication_dashboard. Detail di PANDUAN_BATCH.txt.


--------------------------------------------------------------------------------
2. PASTIKAN DATABASE BENAR (publication_dashboard)
--------------------------------------------------------------------------------

.env di root sudah berisi:

    POSTGRES_DB=publication_dashboard

Jadi perintah di atas otomatis menulis ke publication_dashboard.
JANGAN tambahkan --url (itu hanya untuk test, bisa salah sasaran).

Cek cepat (tanpa menampilkan password):

    python -c "from dotenv import load_dotenv; import os; load_dotenv(); print(os.getenv('POSTGRES_DB'))"

Harus mencetak:  publication_dashboard
Kalau selain itu, BERHENTI dulu.

3. SATU PROFIL (scholar_id)
--------------------------------------------------------------------------------

scholar_id diambil dari URL profil Google Scholar, bagian ?user=:

    https://scholar.google.com/citations?user=8kDg_v4AAAAJ&hl=id
                                       ^^^^^^^^^^^^^^^^^^^^

Jalankan (raw-only, default):

    python src/pipeline/run_pipeline.py --id 8kDg_v4AAAAJ

Perintah ini SUDAH berhenti setelah menyimpan ke RAW
(raw.scholar_scrape_result + raw.scholar_publication).

Kalau scholar_id diawali tanda minus, pakai bentuk "=":

    python src/pipeline/run_pipeline.py --id=-zWuOpYAAAAJ

Berguna:
    --headed      tampilkan browser (kalau kena captcha)
    --batch 5     batasi klik "Tampilkan lainnya" (uji coba)

--------------------------------------------------------------------------------
5. ARGUMEN PENTING
--------------------------------------------------------------------------------

run_pipeline.py:
    --id ID        Scholar ID (juga dipakai sebagai scholar_id saat load).
    --batch N      Batas klik "Tampilkan lainnya" (BATAS PER HALAMAN, bukan
                   jumlah dosen).
    --headed       Tampilkan browser.
    --tanpa-detail Lewati halaman detail per publikasi.
    --raw-only     DEFAULT. Berhenti setelah raw.
    --load-core    Kebalikannya: lanjut ke staging/core. JANGAN dipakai.
    --url URL      Ganti koneksi DB. JANGAN dipakai (biarkan .env).

run_batch.py:
    --file FILE    WAJIB. Path Excel daftar dosen.
    --jeda JEDA    Jeda antar dosen (detik). Default 8.0.
    --lanjut       Lewati dosen yang statusnya sudah terminal.
    --ulang        Paksa ulang semua dosen. Mengalahkan --lanjut.
    --mulai N      Mulai dari baris data ke-N (1-based).
    --progress PATH  Path file progress. Default: data dosen/progress_batch.csv
    --batch N      Diteruskan ke run_pipeline (batas klik, bukan jumlah dosen).


--------------------------------------------------------------------------------
6. EXIT CODE & STATUS
--------------------------------------------------------------------------------

Exit code run_pipeline / batch:
    0   sukses.
    1   gagal load / ada dosen gagal.
    2   gagal scrape / gagal baca daftar.
    130 dihentikan pengguna (Ctrl+C).

Status run di envelope (raw):
    SUCCESS          selesai tanpa penanda parsial.
    PARTIAL_SUCCESS  ada data tersimpan, tapi ditandai parsial (mis. batas
                     --batch tercapai). BUKAN kegagalan: tetap tersimpan ke
                     raw, exit code tetap 0. Cek error_message dan failures.
    BLOCKED / TIMEOUT / NO_DATA / PARSING_ERROR  run gagal (exit 2), tapi
                     tetap dicatat ke raw.

Status dosen di progress CSV (batch):
    OK / OK_RAW / DILEWATI / GAGAL_LOAD / GAGAL_SCRAPE  = TERMINAL
                     (dilewati oleh --lanjut).
    GAGAL          = BUKAN terminal (akan dicoba lagi oleh --lanjut).

Di mode raw-only (default), status load di ringkasan = RAW_ONLY
(bukan LOADED). LOADED hanya muncul kalau pakai --load-core.


--------------------------------------------------------------------------------
7. CEK HASIL DI DATABASE (publication_dashboard)
--------------------------------------------------------------------------------

Dua tabel yang diisi (RAW-only):
    raw.scholar_scrape_result   satu baris per run (envelope).
    raw.scholar_publication     satu baris per publikasi.

Ringkas via PowerShell:

    python -c "from sqlalchemy import create_engine, text; import os; from dotenv import load_dotenv; load_dotenv(); e=create_engine(f\"postgresql+psycopg://{os.getenv('POSTGRES_USER')}:{os.getenv('POSTGRES_PASSWORD')}@{os.getenv('POSTGRES_HOST')}:{os.getenv('POSTGRES_PORT')}/{os.getenv('POSTGRES_DB')}\"); c=e.connect(); print('DB =', c.execute(text('SELECT current_database()')).scalar()); print('run =', c.execute(text('SELECT COUNT(*) FROM raw.scholar_scrape_result')).scalar()); print('pub =', c.execute(text('SELECT COUNT(*) FROM raw.scholar_publication')).scalar())"

Harus mencetak DB = publication_dashboard.

Cek jumlah publikasi & status run terakhir (SQL):

    SELECT scholar_id, COUNT(*) AS jumlah
    FROM raw.scholar_publication
    GROUP BY scholar_id
    ORDER BY jumlah DESC;

    SELECT scholar_id, status, scraped_at
    FROM raw.scholar_scrape_result
    ORDER BY scraped_at DESC
    LIMIT 20;

Cek metadata yang kosong (kolom "status" kelengkapan, sudah ada di
publication_dashboard):

    SELECT status, COUNT(*) FROM raw.scholar_publication GROUP BY status;

    SELECT scholar_id, urutan, detail_volume, detail_issue,
           detail_pages, detail_description, status
    FROM raw.scholar_publication
    WHERE status IS DISTINCT FROM 'yes'
    LIMIT 50;

Arti kolom "status" (dihitung loader saat INSERT, bukan dari scraper):
    yes  = keempat detail_volume/issue/pages/description terisi.
    no   = minimal satu kosong/NULL.
    NULL = baris lama (sebelum migrasi 09), belum divalidasi.


--------------------------------------------------------------------------------
8. MELANJUTKAN BILA TERHENTI / GAGAL
--------------------------------------------------------------------------------

Perilaku --lanjut (penting):
  - Yang TERMINAL (OK, OK_RAW, DILEWATI, GAGAL_LOAD, GAGAL_SCRAPE) DILEWATI.
    Jadi dosen GAGAL_SCRAPE TIDAK diulang oleh --lanjut.
  - Yang GAGAL (error tak terduga) BUKAN terminal -> dicoba lagi.
  - Ctrl+C di tengah satu dosen -> batch berhenti TANPA mencatat dosen itu
    -> --lanjut akan mengulangnya.

Cara melanjutkan:

  (a) Sisa yang belum selesai (paling umum; aman diulang):
        python src/pipeline/run_batch.py --file "data dosen/Data dosen.xlsx" --lanjut

  (b) Ulang SEMUA dosen (mengalahkan --lanjut; hati-hati):
        python src/pipeline/run_batch.py --file "data dosen/Data dosen.xlsx" --ulang

  (c) Ulang SATU profil yang gagal (untuk GAGAL_SCRAPE / kena block):
        python src/pipeline/run_pipeline.py --id <SCHOLAR_ID> --headed
      Perintah (c) tidak mengubah CSV progress; hasilnya tetap masuk raw.

PERINGATAN: file progress sudah berisi riwayat lama (banyak status OK),
jadi --lanjut akan MELEWATI dosen yang pernah sukses. Kalau mau scrape
ulang penuh ke publication_dashboard, pakai file progress BARU:

    python src/pipeline/run_batch.py --file "data dosen/Data dosen.xlsx" --progress "data dosen/progress_batch_baru.csv" --lanjut

atau pakai --ulang.

Jangan buka progress_batch.csv di Excel (locale Indonesia memakai ";").
Lihat isinya dengan PowerShell:

    Import-Csv "data dosen\progress_batch.csv" | Group-Object status

10. CATATAN TEKNIS (untuk laporan)
--------------------------------------------------------------------------------

  - Raw-only adalah DEFAULT (sejak P13). --load-core harus eksplisit.
  - Default --lanjut: batch berjalan lagi, yang sudah terminal dilewati.
  - Argumen diteruskan pakai bentuk --nama=nilai, supaya scholar_id yang
    diawali "-" tidak dianggap flag.
  - Kolom status kelengkapan (P24) sudah diterapkan ke publication_test
    (P26) dan publication_dashboard (P27). Migrasi 07 (detail_doi) dan
    08 (profile_volume/issue/pages) juga sudah diterapkan ke
    publication_dashboard (P28), jadi skema dashboard kompatibel dengan
    loader RAW 25 kolom.
  - status dihitung dari KEEMPAT field detail; profile_* TIDAK dipakai
    sebagai fallback. Baris lama tetap NULL (tanpa backfill).
  - status = 'no' tidak membedakan "tidak tersedia di Scholar" vs
    "ekstraksi detail gagal".
